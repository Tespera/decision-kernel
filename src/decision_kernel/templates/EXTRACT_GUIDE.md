# 抽取指南：决策片段 → 裁决记录（所有批次共用）

你的任务：把一批**决策片段**逐条转成结构化的「裁决记录」。

## 最高原则：你是转录员，不是分析师

下游会用你的输出去提炼「用户的决策依据」，并长期指导 AI 的行为。最危险的错误是：
把 AI **自己归纳的标签**当成「用户的原则」写进去——之后它会被反复引用、拿来做决策依据，
等发现是错的时候，已经误导了一大串判断。所以：

- `verbatim` 字段**必须是用户逐字原话**，能在输入片段里原样搜到。一个字都不许改写、润色、翻译、补全。
  抽完会有脚本（`dk verify`）逐条比对，对不上的会被打回。
- 你的判断只能出现在 `axis` / `domain` / `reusable` / `confidence` 四个字段里。
- 拿不准就 `confidence: "low"`，或者干脆丢弃。**漏掉一条的代价，远小于编出一条。**
- 严禁推测用户的动机、性格、心理。只记他做了什么裁决、说了什么话。

## 输出格式（JSON Lines，一行一条）

```json
{"id":"J1-001","date":"2026-08-13","proj":"blog","sess":"fc41b6f7",
 "situation":"Claude 问演示文稿用哪套主题",
 "options":["深色图谱","炫光紫绿","色谱图表"],
 "decision":"选深色",
 "verbatim":"就深色，和上次那份汇报统一",
 "axis":"跨材料视觉一致性 > 单份材料的表现力",
 "domain":"aesthetics",
 "reusable":true,
 "confidence":"high"}
```

- `id`：`<批次名>-<三位序号>`，批次名即你拿到的批次文件名（如 `J1`）。
- `date` / `proj` / `sess`：照抄片段里的同名字段，它们是证据链地址。
- `situation`：当时在决什么。一句话。
- `options`：明确摆出来的备选项；没有就 `[]`。
- `decision`：用户实际的裁决（可以是「否决全部、另提第三条路」）。
- `verbatim`：**逐字原话**，最长 200 字。太长就截取最能体现裁决的那一句——截取不算改写；
  中间跳过内容用 `…` 连接，各段都必须是原文。
- `axis`：这次裁决体现的**权衡轴**，写成「A > B」或「A 优先于 B」。这是全流程最有价值的字段，
  它让下游能把散落的裁决归到同一个判断依据下。想不出清晰的轴就填 `""`。
- `domain`：四选一
  - `collab` 协作方式（何时该问用户 / 何时自己定 / 汇报详略 / 沟通风格）
  - `tech` 技术与方案取舍
  - `product` 产品与业务判断
  - `aesthetics` 表达与视觉审美
- `reusable`：**换一个完全不同的项目，这条还成立吗？** 成立 `true`，绑死在具体业务 / 表名 / 页面上 `false`。
  这个字段决定它能不能上升为通用依据，认真填。
- `confidence`：`high` 表述明确无歧义 / `medium` 意思清楚但有解读空间 / `low` 勉强算裁决。
- 可选 `src_note`：原话其实出自 `prev_user`（上一条输入）等归属有偏差时，写明情况，不要硬塞。

## 必须丢弃的（不要为了凑数硬转）

1. 纯状态询问：「做完了吗」「卡在哪了」
2. 纯 bug 报告 / 纯事实提问：「出错了打不开」「这个文件在哪」
3. 纯确认、无信息量：「OK」「继续」「好的」
4. 纯粹自发的新需求——用户提出要做某功能，但**没有在既有选项间取舍，也没否定任何东西**
5. 纯业务内容决定（「节点改成 12 个」「字段叫 xxx」）——**除非**其中体现了可迁移的判断口径

第 5 条容易误伤。反例：「你全盘想一下这里的设计逻辑，不要单点看问题」——虽然出现在具体业务里，
但它是对**工作方式**的要求，`domain: collab`、`reusable: true`，必须保留。

## 一条片段可以产出多条记录

用户一段话里同时否决 A、选择 B、又立了条规矩，就拆成 2–3 条。反过来，大量片段会产出 0 条，
这完全正常——**预期丢弃率 40–60%**。

## 输入片段的字段

- `kind`：
  - `A` = Claude 用 AskUserQuestion 正式提问：`ask` 是问题与选项全文，`answer` 是用户的选择，`follow` 是紧接着的补充
  - `B` = Claude 末尾在征询（`claude_ask`）+ 用户回答（`user_reply`）
  - `C` / `D` = 用户的反应：`claude_ctx` 是上文，`user_msg` 是用户的话（D 是用户在规定 AI 怎么工作）
  - `E-meta` / `E-fix` = **只有用户侧、没有 Claude 的回复**；`prev_user` 是同会话上一条用户输入，
    只是弱线索，不要当成 Claude 说过的话
- E 类缺上下文，`situation` 只写你从用户话里直接读出来的，**不要脑补 Claude 当时做了什么**。
